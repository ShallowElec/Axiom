# 00 · Axiom 品牌与视觉系统

> 状态：设计稿，待批准。  
> 目标不是把现有界面“换一套颜色”，而是消除玩具感，建立一种可长期工作的工程仪器气质。

## 1. 诊断：为什么现在像玩具

现有界面并非没有设计，而是把“编辑性演示”的设计语言用在了“工程工具”上：

| 现有特征 | 问题 | Axiom 的替代 |
|---|---|---|
| 奶油纸张 + 深绿舞台 + 青柠/珊瑚/薄荷多色 | 色相多、情绪强，像展览海报；颜色承担了过多语义 | 纯白纸面 + 墨黑 + 单一天蓝阶；语义依赖文字/线型/形状 |
| 12–20px 大圆角卡片、浮起阴影、模糊背景 | 塑料感、层级靠“漂浮”而非网格 | 0–2px 圆角、1px 硬线、无阴影；层级靠留白与分隔线 |
| 8.5px 全大写英文标签、衬线大标题 | 字号极端、中文可读性差；像杂志而不是仪表 | 11–13px 工作字号、无衬线标题、等宽技术标签 |
| 巨大的播放按钮、彩色提示、彩色 toast | 操作反馈抢过内容 | 28px 工具按钮、黑底短提示、状态用文本与几何 |
| 模态弹窗承担主流程 | 工作被打断，状态不连续 | 主流程全部在 dock；仅编辑/确认使用临时面板 |
| 渐变、发光、hover 抬升、弹簧动画 | 视觉噪音，和数学的确定性冲突 | 平面、短促、只改颜色/线宽；尊重 reduced motion |

**工程感不是“更暗”或“更多灰”，而是：清晰的结构、稳定的网格、可预测的状态、让数据成为主角。**

## 2. 品牌

### 2.1 名称与声音

- 产品名：**Axiom**。
- 中文正文可称“公理”，但在窗口、菜单、安装包、启动页、标题栏中只使用 **Axiom**，不并列“矩阵工坊”。
- 一句话定位：**A computational workbench for mathematics you can inspect.**
- 中文定位：**可检查、可组合、可重放的数学工作台。**
- 品牌语气：短、准确、不过度热情。用“运行 / 步骤 / 来源 / 形状 / 精度”，不用“魔法 / 惊艳 / 一键 / 秒懂”。

### 2.2 字标

- 字标：`AXIOM`，全大写，几何无衬线，字距收紧但不做艺术字。
- 辅助标识：`MATH WORKBENCH` 或 `COMPUTATIONAL WORKBENCH`，10px 等宽，字距 0.14em。
- 图标方向：黑底/白底方形内的几何 “A” 或公理符号；不用渐变、不用发光、不用圆角头像式图标。
- 品牌主色不是青柠，而是 **INK + SKY**。天蓝只在需要指示/数据/焦点时出现。

## 3. 设计原则

1. **结构和数值优先。** 任何装饰若不能帮助定位、比较或理解，就删除。
2. **硬边界。** 面板、单元格、表格、按钮都以直角或 2px 微圆角结束；不使用悬浮卡片。
3. **一套色相。** 白、黑、天蓝。语义差异通过标签、线型、符号、排布实现，不靠彩虹。
4. **等宽数据。** 数字、ID、shape、dtype、时间、坐标全部使用 tabular numerals；数字不跳动对齐。
5. **密度可读。** 默认紧凑但不拥挤；中文最小 11px，正文 12px；大量信息用行、列、分隔线而非卡片。
6. **单一事实源。** 选中、游标、视图高亮从同一组 ID 派生；同一对象在不同面板中必须能对应。
7. **运动是状态变化。** 动效用于说明“从哪到哪”，不做弹跳、发光、漂浮和装饰性循环。
8. **颜色不是唯一通道。** 所有关键状态都有文字或形状冗余。
9. **空态克制。** 不用插画、不用口号；用一条可执行提示和一个动作。
10. **深色是第二主题。** 浅色是默认工作环境；深色用于夜间/演示，不改变语义。

### 4.2 深色主题（可选）

深色不是旧深绿舞台的翻新，而是另一套“白字 + 亮蓝”的墨水屏/仪器夜模式。

| Token | 值 | 用途 |
|---|---|---|
| `--ax-paper` | `#0C0F11` | 深色背景 |
| `--ax-surface` | `#121619` | 面板 |
| `--ax-surface-2` | `#171C20` | 悬停、选中底 |
| `--ax-ink` | `#F3F6F8` | 正文、标题；对背景约 17.5:1 |
| `--ax-ink-2` | `rgba(243, 246, 248, 0.68)` | 次要文字 |
| `--ax-ink-3` | `rgba(243, 246, 248, 0.38)` | 禁用、占位 |
| `--ax-blue` | `#8FD3F0` | 亮蓝文字/激活线；对背景 11.65:1 |
| `--ax-blue-2` | `#40A6D6` | 强蓝线/数据中间阶；6.99:1 |
| `--ax-blue-deep` | `#1F6F9C` | 仅用于边界、图表底色，不作为正文（3.49:1） |
| `--ax-rule` | `rgba(243, 246, 248, 0.14)` | 分隔线 |
| `--ax-rule-strong` | `rgba(243, 246, 248, 0.28)` | 面板/输入边界 |

| `--ax-selected-bg` | `rgba(143, 211, 240, 0.12)` | 选中底 |

深色里不出现旧奶油白、青柠绿、珊瑚橙、暖棕灰。不得用大面积亮蓝填充；亮蓝主要用于文字、1px 线、游标和小面积状态。

### 4.3 对比度约束

- 白底正文：`INK` 19.68:1；`SKY 700` 5.51:1。
- 白底 `SKY 500` 2.75:1：**只能 ≥32px 大字或非文字线条/填充**。
- 白底 `SKY 300` 1.65:1：**只作装饰/底纹**。
- 深色底正文：`#F3F6F8` 17.54:1；`#8FD3F0` 11.65:1；`#40A6D6` 6.99:1。
- 任何 11–13px 中文标签不得使用 `SKY 500/300` 或深色 `SKY 700` 作为文字色。

## 5. 数值色阶与矩阵语义

### 5.1 只使用单色相 sequential ramp

数值大小使用天蓝亮度/饱和度阶，不使用红绿 diverging。零为白底；正负号、数字、形状和线型作为冗余语义。

#### 浅色矩阵单元阶

| 阶 | 填充 | 文字 | 说明 |
|---:|---|---|---|
| 0 | `#FFFFFF` | `#0B0B0B` | 0 / 缺失 / 空白 |
| 1 | `#F4FBFE` | `#0B0B0B` | 极小 |
| 2 | `#E3F5FC` | `#0B0B0B` | 小 |
| 3 | `#C9ECF8` | `#0B0B0B` | 中低 |
| 4 | `#A6DDF2` | `#0B0B0B` | 中 |
| 5 | `#70C6E7` | `#0B0B0B` | 中高 |
| 6 | `#40A6D6` | `#0B0B0B` | 高（黑字 7.16:1） |
| 7 | `#1F6F9C` | `#FFFFFF` | 最高（白字 5.51:1） |

- 负值使用相同 magnitude 阶，但显示显式负号 `−`，单元格左边加 2px 黑实线；负号不是颜色。
- 零值保持白底，显示 `0`，不与其他空白混淆。
- 选中单元：2px 黑色外框 + 浅蓝选中底；不使用“高亮发光”。
- 来源单元：1px 天蓝虚线内框；结果单元：1px 黑实线内框 + 右下角 `=` 标记。
- 错误单元：45° 黑色 hatch + `ERR` 文字；不使用红色。

#### 深色矩阵单元阶

从 `#121619` 到 `#8FD3F0` 的连续阶；高亮端使用深色字。所有单元保留 1px 规则线，避免大面积蓝块。

### 5.2 语义角色不靠色相

旧界面用绿/珊瑚/琥珀区分输入/结果/观察。新系统全部改为：

| 角色 | 编码 |
|---|---|
| 输入 / 来源 | `SOURCE` 文字 + 1px 虚线 + 左对齐标签 |
| 生产 / 当前 | `LIVE` 文字 + 1px 天蓝实线 + 浅蓝底 |
| 中间值 | `STEP` 标签 + 普通黑线 |
| 结果 | `RESULT` 标签 + 双线底边 / 黑色 `=` |
| 矩阵 | 网格图标 + `matrix` 标签 + shape |
| 标量 / 数字 | 点/单值图标 + `scalar`/`number` 标签 |
| 梯度 / 反向（未来） | 双线 + 向上箭头 + `grad` 标签 |
| 精度转换（未来） | 阶梯状/虚线 + 输入/输出 dtype 文本 |
| 错误 | hatch + `ERROR` + 错误码 |
| 警告 | 三角 + `WARN` + 文本 |
| 锁定 / 不可用 | 灰色/hatch + `LOCKED` + 原因 tooltip |

**颜色只能在语义已知后表示“强弱/选中/数值”，不能表示类别本身。**

## 6. 字体与数字

### 6.1 字体族

```text
UI:      IBM Plex Sans, PingFang SC, Microsoft YaHei UI, Noto Sans CJK SC, sans-serif
技术标签: IBM Plex Mono, SFMono-Regular, Cascadia Code, Menlo, monospace
公式:    KaTeX 数学字体（不由 UI 字体替代）
```

- IBM Plex Sans/Mono 建议在代码阶段自托管，避免网络与跨平台字体漂移；中文回退系统字体。
- 不使用 Iowan/Palatino/Songti 等衬线字体做 UI 标题；衬线只属于公式排版。
- 不使用全大写装饰性大标题；技术标签才使用 uppercase + letter-spacing。

### 6.2 字号与行高

| Token | 字号/行高 | 用途 |
|---|---|---|
| `micro` | 10/14 | 仅英文技术标签、表头、坐标；中文不进入这一级 |
| `caption` | 11/16 | 中文辅助说明、状态、单位 |
| `body` | 12/18 | 主要正文、表格内容、按钮 |
| `body-strong` | 13/18 | 强调、选中对象名 |
| `section` | 15/22 | 面板标题、视图标题 |
| `display` | 18/24 | 空态、工具页标题；产品 chrome 不使用 32+ |
| `math` | KaTeX | 公式，可随视图放大 |

- 默认中文字间不额外加 letter-spacing；技术英文标签 `letter-spacing: 0.08em–0.14em`。
- 数字使用 `font-variant-numeric: tabular-nums slashed-zero;`；矩阵值、shape、时间、run ID 必须等宽。
- 不用 8px 正文，不用 40px 非公式标题。

## 7. 几何、密度、层级

### 7.1 形状

- 面板/输入/按钮/矩阵单元/表格：`border-radius: 0`。
- 极小控件（如 16px 图标按钮、tag）：最大 `2px`。
- 禁止 8/12/16/20px 大圆角；禁止胶囊按钮。
- 线宽：常规 1px；重点状态 2px；不使用模糊边框。
- 阴影：无。仅浮层/对话框使用实线边框 + 不透明遮罩；不使用模糊/毛玻璃。
- 渐变：无。
- 背景图案：只在画布使用 1px 技术网格（透明度 ≤ 4%），不覆盖内容。

### 7.2 间距与尺寸

- 基础单位 4px；布局常用 8/12/16/24/32。
- 顶部命令栏 44px。
- 活动栏 46px。
- 资源栏 240–272px（默认 264）。
- 检查器 300–336px（默认 320）。
- 底部 dock 220–280px（默认 236）；折叠 30px。
- 状态栏 22px。
- 面板头 30px；工具条 32px；表格行 28px；按钮 26/30px；输入 28px。
- 可点击目标不小于 24×24px；主要工具 28×28px。

### 7.3 层级

工程界面靠 1px 规则、留白和字号建立层级，不靠卡片阴影：

1. 窗口背景（白）
2. 面板边界（细线）
3. 面板头（灰黑小字 + 分隔线）
4. 内容表格（行线）
5. 选中（浅蓝 wash + 黑色左/下标记）
6. 浮层（黑色遮罩 + 实线面板，无模糊）

## 8. 组件规范

### 8.1 按钮

| 类型 | 外观 | 交互 |
|---|---|---|
| Primary | 黑底白字，0 radius，26–30px 高 | 运行、确认；hover 背景 `#262626`；active 位移 0 |
| Secondary | 白底，1px `rule-strong`，黑字 | 次操作；hover `sky-100` |
| Tertiary | 透明，黑字，hover 浅蓝 wash | 工具条、列表行内动作 |
| Danger | 白底，1px 黑，文字 `!` + “删除” + 黑 hatch | 不使用红色；二次确认 |
| Disabled | 透明，ink-3，hatch 或无填充 | 点击无效，tooltip 解释原因 |

- 图标按钮 24×24 或 28×28；图标 16px / 1.5px stroke。
- 不使用 pill、渐变、浮起阴影。
- 按压只改变背景/边框，不缩放。

### 8.2 输入与选择

- 输入框：白底、1px 线、0 radius、内边距 6px 8px；focus 1px `sky-700` + 2px offset。
- 数字输入使用 mono；非法输入用黑 hatch 边 + 文本 `INVALID`，不用红色。
- 下拉/菜单：白底、1px 黑/深线、无圆角、无阴影；选中行 `sky-100` + 左侧 2px 黑线。
- 搜索框：mono 前缀 `⌕` 或 `SEARCH` 标签；占位文字 11px。

### 8.3 Tabs

- 高度 30px；底部 2px 透明；选中为 2px 黑线；hover 仅文字变黑。
- 不使用胶囊背景、不使用彩色填充。
- 底部 dock 的 tab 与中央视图 tab 使用同一规则，避免两套标签语言。

### 8.4 面板与分隔

- 面板头：11px mono uppercase + 30px 高 + 1px 底线；标题左对齐，状态右对齐。
- 分隔条：1px `rule`；拖拽命中区 5px；hover 时线变 `sky-700`。
- 折叠按钮：方形 +/−，16px。
- 面板不做“卡片套卡片”；一个区域最多一层边界。

### 8.5 表格 / Trace

- 表头 24px，10px mono uppercase，右对齐数值列。
- 行 28px；无斑马纹；hover `rgba(11,11,11,0.035)`；选中 `sky-100` + 左侧 2px 黑线。
- 数值右对齐、等宽、保留显式符号；shape `2×2`；dtype `Q` / `f32` 使用 mono。
- 选中的行必须在 Trace、时间轴、检查器、场景中保持同一 ID。
- 超长内容使用省略号，hover 提供完整 tooltip；不通过换行撑高行。

### 8.6 状态与提示

- 状态 = 文本 + 小几何标记；不使用绿/黄/红圆点作为唯一信号。
- 成功：`✓` + `完成`；警告：`△` + `WARN`；错误：`×` + `ERROR`；派生：`D` + `DERIVED`。
- Toast：黑底白字、1px 白/浅蓝边、0 radius、底部左侧；持续 2.4s；不遮挡时间轴控制。
- 错误块：1px 黑边 + hatch 顶栏，正文说明原因/修复/错误码；不使用红底。
- 加载：线性进度条（黑/蓝），不使用旋转发光圆环。

### 8.7 对话框与浮层

- 主流程不靠 Dialog：公式、算法、运行历史、Trace 都在 dock。
- 仅 Matrix Editor、确认、命令面板使用临时层。
- 遮罩：`rgba(11,11,11,0.36)`，不使用 blur。
- 面板：白、1px 黑、0 radius、无阴影；最大宽度 760–960px；键盘 focus trap。
- 关闭：右上角 24px 方形 ×；Esc 可关。

### 8.8 图标

- 16px（工具栏）/18px（活动栏），1.5px stroke。
- 单色；选中态用黑色或蓝色线，不用彩色填充。
- 文档、运行、公式、算法、终端、图层、设置使用统一几何语言；不使用 emoji。
- 图标必须配文字/tooltip；图标不是唯一标签。

## 9. 运动与声音

- 过渡时长 80/120/160ms；只用于 opacity、color、border-color、transform（小于 2px）。
- 不使用弹簧、bounce、发光、缩放 1.05、漂浮。
- 重播中的矩阵扫描/累加可以使用 160–320ms 的线性/短 ease-out；只表达数据方向。
- 默认遵守 `prefers-reduced-motion`：直接跳到步骤终态，只保留静态高亮；仍可手动逐帧。
- 不加入声音作为默认反馈。

## 10. 文案与语言

- 产品 chrome：中文标签 + 稳定英文技术词（RUN, TRACE, REPLAY, SHAPE, DTYPE, SOURCE）。
- 不出现营销句、感叹号、emoji、拟人化错误。
- 示例：
  - 空态：`没有运行记录。按 Ctrl/⌘ + Enter 运行当前表达式。`
  - 派生 trace：`DERIVED TRACE · 由当前故事板派生，不是内核级执行记录。`
  - 不兼容：`无法从该步骤分支。该运行没有记录可恢复的输入快照。`
  - 警告：`WARN · 内维不匹配：2×3 × 2×2。`
- 中文正文允许“公理”，但 UI 主品牌只用 Axiom。
- 双语策略：本阶段以中文字段为主，英文用于技术语义；真正的 i18n 资源化在后续做，不在本阶段引入半成品语言开关。

## 11. 可访问性

- 所有正文对比度达到 WCAG AA；`SKY 500/300` 不当正文。
- 键盘焦点始终可见：1px `sky-700` + 2px offset；深色为 `sky-300`。
- 主操作有键盘等价：运行、重播、步进、切视图、聚焦面板、关闭浮层。
- 时间轴/表格提供文本语义；播放游标变化可被屏幕阅读器读出。
- 颜色不是唯一通道；蓝色阶必须配数值、符号和标签。
- 尊重减少动态效果；动画可关闭。
- 触控/鼠标命中区最小 24px；主要按钮 28/30px。
- 不依赖 hover 才能获得关键信息；tooltip 信息必须在检查器/表格中可展开。

## 12. 主题切换与 token 规则

- 默认主题：**Light**。
- 标题栏/设置提供 Light / Dark 切换；本阶段不持久化，刷新回到 Light。
- 所有颜色通过 CSS 自定义属性（`--ax-*`）消费；组件不写死 hex。
- 数据色阶单独 token：`--ax-scale-0` … `--ax-scale-7`，浅/深主题各自映射。
- 语义类别 token 只用于线型/小面积，不用于整块背景。
- 矩阵/图表输出必须同时提供表格 fallback；复制/导出文本不受颜色影响。
- 旧 `--paper/--night/--lime/--coral/--amber` 等 token 在代码阶段整体移除，不做双 token 兼容层。

### 12.1 建议 token 命名

```text
--ax-paper / --ax-surface / --ax-surface-2
--ax-ink / --ax-ink-2 / --ax-ink-3
--ax-sky-700 / --ax-sky-500 / --ax-sky-300 / --ax-sky-100
--ax-rule / --ax-rule-strong / --ax-rule-ink
--ax-focus / --ax-selected-bg
--ax-scale-0 ... --ax-scale-7
--ax-font-ui / --ax-font-mono
--ax-radius-0 / --ax-radius-1
--ax-control-sm / --ax-control-md
--ax-motion-fast / --ax-motion-base / --ax-motion-slow
```

## 13. 决策记录

**已决定**

- Axiom 英文主品牌；中文正文可称“公理”。
- 浅色为默认，深色是可切换的第二主题。
- 纯白/墨黑/天蓝单色相；数据用单色阶；旧绿/珊瑚/暖纸张退出。
- 0–2px 圆角、1px 硬线、无阴影/渐变/模糊。
- UI 正文最小 11px 中文、12px 正文；不再使用 8px 正文。
- 主要工作区不使用模态弹窗。
- 错误不使用红色，使用文字/hatch/符号编码。
- 当前阶段不持久化主题选择。

**待批准/待定**

- IBM Plex Sans/Mono 是否在第一刀就自托管（建议是，避免平台字体漂移）。
- 是否允许为超大公式/图表使用 28–32px 的 `SKY 500` 大字（仍禁止正文）。
- 词标是否以后做独立矢量字形；本阶段先用高质量字标。
