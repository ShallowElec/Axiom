# Axiom · 设计重构包

> **状态：DESIGN DRAFT — 尚未写代码，等待批准。**  
> **基准日期：** 2026-10-26  
> **品牌：** Axiom（英文主品牌；中文正文可称“公理”）  
> **本阶段目标：** 在不重写现有精确矩阵内核的前提下，把“矩阵工坊”重构为工程仪器感的 Axiom 工作台，并建立可检查的 Run / Replay 闭环。

## 0. 为什么现在先写文档

现有应用已经具备可靠的计算核心、95 项测试、逐帧故事板、调试注册表与 Scene 原型，但界面仍以“演示海报”为主要气质：奶油纸张、深色舞台、青柠/珊瑚多色强调、大圆角卡片、衬线大标题、弹窗优先。它更像一个漂亮的数学展览，而不是一套可以长期工作的工程软件。

这次重构不是换一层皮。它同时改变四件事：

1. **品牌与视觉语言**：Axiom，工程纸面，白底黑字天蓝阶，低圆角、硬边界、高信息密度。
2. **信息架构**：从“侧栏 + 舞台 + 检查器 + 浮层调试台”变为 IDE 式可停靠工作台。
3. **执行与重播模型**：从“播放预编译动画”变为“运行不可变记录上的可检查重放”。
4. **代码边界**：把当前混合在 `stories.ts` 与 `App.tsx` 中的计算、表示、UI 状态拆成可测试的 Run / Trace / Presentation / Replay 流程。

## 3. 设计不变量

这些是后续所有实现和评审的硬约束：

1. **计算不可藏在渲染器里。** 渲染器只消费 Presentation IR / Scene，不调用数学函数。
2. **重播不可重新求值。** 拖动时间轴、切视图、选步骤不会产生新的数学结果。
3. **运行不可变。** 完成后 run 与其 trace 不再被编辑；新参数产生新 run。
4. **派生 trace 必须诚实标注。** 第一阶段从现有故事板派生执行事件，必须标出 `provenance: derived`，不能伪装成内核原生 trace。
5. **颜色不是唯一语义通道。** 矩阵/标量/结果/梯度/错误同时用文字、线型、图标、形状或模式编码。
6. **只用白、黑、天蓝。** 不铺渐变、不发光、不做彩色底托、不新增绿/红/紫强调色。
7. **工程界面不是海报。** 界面 chrome 不出现营销式大标题和情绪化文案；公式本身可以大，操作 chrome 必须克制。
8. **第一阶段没有持久化。** Session、runs、replay 状态都只在内存；不写迁移桥、不承诺旧数据兼容。
9. **所有主操作有键盘路径。** 播放、逐帧、切视图、选中、运行、聚焦面板均可用键盘完成。
10. **先批准，后写代码。** 本包完成后停下来等待明确批准。

## 4. 本阶段明确不做

- 不实现 Rust/WASM 内核、SQLite 项目文件、`.mathproj`/`.axiomproj`。
- 不实现真正的内核级 trace、真实 step checkpoint、原生 MX/FP4、AD/VJP。
- 不把“分支运行”伪装成已经可用；第一版先把不可变 run 与 rerun/lineage 做真，step-level fork 需要等内核 snapshot 能力。
- 不做云端、账户、协作、插件市场。
- 不做完整任意嵌套公式编辑器；第一刀是让现有公式能力进入新的 Axiom 外壳，公式编辑器单独排期。
- 不改数学语义，不为了视觉效果歪曲 shape/顺序/规则。
